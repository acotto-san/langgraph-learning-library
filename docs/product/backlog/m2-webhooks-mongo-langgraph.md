# Milestone 2 — Webhooks, MongoDB, and LangGraph Replies

This milestone moves ingestion to webhooks, adds MongoDB storage with a repository interface, introduces LangGraph-driven replies, and improves observability and CI.

## Story S6: Webhook ingestion
**Story**: As a bot operator, I want Telegram updates delivered via an HTTP webhook so I don’t rely on polling.  
**Rules**:
- R1: Expose an HTTPS webhook endpoint with a secret path/token to receive Telegram updates.
- R2: Accept only valid Telegram POST payloads; respond 200 quickly to avoid retries; reject other methods/paths.
- R3: Validate/update metadata (`chat_id`, `user_id`, `message_id`, `timestamp`) and keep per-chat partitioning intact.

## Story S7: MongoDB storage
**Story**: As a developer, I want to persist messages in MongoDB via a repository interface to support scaling and indexing.  
**Rules**:
- R1: Insert message documents with chat/user metadata and timestamps; maintain order via `timestamp` or `message_id`.
- R2: Enforce a per-chat partition (e.g., index on `chat_id`, `timestamp`); no cross-chat bleed.
- R3: Handle connectivity/write failures gracefully (log error, surface failure; no partial writes).

## Story S8: LangGraph replies
**Story**: As a bot operator, I want the bot to send replies generated by a LangGraph agent so users get responses.  
**Rules**:
- R1: Forward incoming text to the LangGraph agent and await a reply (with a timeout).
- R2: Send the agent’s reply back to the same chat via the bot; do not echo the original message as the reply.
- R3: On agent failure/timeout, send a graceful fallback message and log the error.

## Story S9: Observability (logging/metrics)
**Story**: As a developer, I want structured logs and basic metrics so I can trace requests and spot failures.  
**Rules**:
- R1: Log inbound webhook requests and outbound bot replies with chat/message identifiers and correlation/trace ids.
- R2: Log errors with stack/exception info; distinguish info vs. warning vs. error.
- R3: Expose or emit simple metrics (e.g., counts for received messages, sent replies, failures).

## Story S10: CI pipeline
**Story**: As a developer, I want CI to gate merges with linting, typing, and tests.  
**Rules**:
- R1: CI runs `ruff`, `mypy`, and tests on each push/PR; all must pass.
- R2: CI fails fast on violations; reports failures clearly.
- R3: CI avoids leaking secrets (no tokens in logs/config).
